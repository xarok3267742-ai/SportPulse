# Спорт Пульс

Нативное Android-приложение на Kotlin про спортивные события России и СНГ, проверку качества данных и ответственное отношение к ставкам.

Футбольное расписание на сегодня и два следующих дня загружается через защищённый серверный шлюз, фильтруется по России и странам СНГ и сохраняется в закрытом локальном кеше. Приложение не принимает ставки, не проводит денежные операции, не показывает коэффициенты и не обещает результат. Расписание внешнего источника не считается подтверждением формы, состава или аналитического вывода.

## Release-подпись

Релизный bundle подписывается upload-ключом, который не хранится в Git. Локальная сборка читает `.local/release-signing.properties`; CI может передать те же значения через переменные окружения:

```properties
storeFile=.local/sport-pulse-upload.jks
storePassword=секрет
keyAlias=sport-pulse-upload
keyPassword=секрет
```

```text
SPORT_PULSE_RELEASE_STORE_FILE
SPORT_PULSE_RELEASE_STORE_PASSWORD
SPORT_PULSE_RELEASE_KEY_ALIAS
SPORT_PULSE_RELEASE_KEY_PASSWORD
```

Команда сборки: `./gradlew bundleRelease`. Keystore и пароли необходимо хранить в отдельной защищённой резервной копии: без upload-ключа нельзя подписывать последующие обновления тем же ключом.

Готовый подписанный AAB версии `3.0.0 (72)`, публичный upload-сертификат и контрольные суммы находятся в каталоге [`release`](release/README.md).

## Главное

- «Штаб решения» собирает выбранный матч в один сценарий: тип проверки, тезис, сильный контраргумент, наблюдаемое условие отмены и три ответа «что изменилось / чего не хватает / что делать сейчас». Статус `Стоп / Наблюдать / Факты готовы` закрывается при незаполненном замысле, неподходящем рынке, критическом пробеле, устаревших данных или непроверенной альтернативной версии. Встроенные «История» и «Профиль» оценивают дисциплину процесса без коэффициентов, сумм, доходности и угадывания исходов. [Правила Штаба](docs/decision-desk.md).
- Новая adaptive-иконка соединяет спортивную траекторию, проверочный импульс и одну точку события. Цветной foreground работает с круглой и скруглённой маской, а Android 13+ получает отдельный monochrome-слой для тематических иконок. [Концепция и техническая схема](docs/app-icon.md).
- Онлайн-каталог через защищённый серверный шлюз: до 60 футбольных событий России, Беларуси, Казахстана, Армении, Азербайджана, Кыргызстана, Узбекистана, Таджикистана, Туркменистана и Молдовы на трёхдневном окне.
- «Честный поиск событий»: команда, турнир, регион и вид спорта сопоставляются локально, кириллица находит латинские названия и наоборот. Каждая карточка показывает детерминированный «След поиска» — поле, по которому прошли токены. Результаты сохраняют порядок каталога без персонализации и скрытого рейтинга. [Открытая спецификация](docs/event-search.md).
- «Когда»: единый верхний фильтр делит текущую выдачу на `Сейчас`, `Сегодня`, `Завтра`, `Позже`, `Завершены` и `Проверить` в выбранном часовом поясе. Карточка объясняет причину выбранной группы; переносы, прерывания, отмены, технические решения, прошедший старт без актуального статуса и события без времени не маскируются под обычный финал или предстоящий матч. [Открытая спецификация](docs/feed-timeline.md).
- «Матч-центр» по умолчанию выводит на первый экран четыре компактные строки со статусом, временем, турниром и закладкой. Событие с первой проверкой гарантированно остаётся в видимом наборе, а полный исследовательский набор остаётся в «Инструментах». [Открытая спецификация](docs/feed-focus.md).
- «Матч-день» одним снимком показывает число идущих сейчас, сегодняшних, требующих проверки и сохранённых событий. Выразительный Fira Sans Condensed используется для спортивного табло, заголовков и команд, спокойный Golos Text — для объяснений и длинного чтения. Оба кириллических шрифта встроены в APK и не загружаются из сети. [Правила типографики](docs/typography.md).
- Фирменная визуальная система спортивного досье: полноширинное изображение выбранного события, единая тёмная навигационная лента, операторское табло доказательств и светлый рабочий протокол. Цвет дублируется числом и текстом, а графическая схема имеет accessibility-описание. [Открытая спецификация](docs/ui-system.md).
- «Пульс обновления» честно сравнивает два последних снимка API: объединяет изменения времени, статуса и счёта по матчу, отдельно показывает появление или отсутствие события в выдаче и не называет отсутствие отменой без подтверждения.
- «Карта данных» начинается в первом просмотре анализа и показывает все пять факторов отдельно: `нет источника`, `1 источник`, `2 источника`, необходимость обновления или истёкший срок. Ровно одна строка выделяется как следующий шаг. Кнопка `?` объясняет статусы без выхода из матча; карта не показывает вероятность исхода и не зависит от субъективной шкалы. [Открытая спецификация](docs/plain-analytics.md).
- «Протокол проверки» превращает главный пробел в три контекстных шага: первичный факт, независимую сверку и стоп-правило. Отдельные сценарии предусмотрены для формы, состава, нагрузки, контекста и источников; правило завершения учитывает эффективный уровень доказательств. Формальные ограничения опубликованы в [спецификации протокола](docs/verification-recipe.md).
- «Факт-квитанция» связывает один проверяемый тезис с первичным и необязательным вторым источником, явной связью между ними и уровнем полноты. Одинаковый домен автоматически считается одной цепочкой, конфликт fail-closed снижает эффективное подтверждение, а одна атомарная запись согласованно обновляет выбранный фактор. Правила опубликованы в [спецификации факт-квитанции](docs/fact-receipt.md).
- «Реестр фактов» собирает пять квитанций события в одном прокручиваемом окне, показывает тезисы, срок, временную согласованность и происхождение, даёт прямой переход к любому фактору и детерминированно ставит первым повреждение, конфликт или пропуск. «Факт-маршрут» открывает этот следующий фактор и после сохранения, удаления или возврата показывает заново вычисленную сводку. Реестр ничего не записывает сам и получает общую SHA-256-метку. Правила опубликованы в [спецификации реестра](docs/fact-register.md).
- «Кросс-эхо» нормализует домены и названия источников из всех валидных квитанций, обнаруживает одно происхождение в разных факторах и предлагает первую квитанцию для разнообразия. Сигнал fail-neutral: он показывает общую зависимость, но не понижает кворум автоматически. Формальные правила опубликованы в [спецификации карты происхождений](docs/cross-source-map.md).
- Первый запуск содержит подтверждение возраста и обучение из пяти шагов. Содержимое прокручивается отдельно, а нижние команды остаются доступными при системном шрифте 200%. В разделе «Гид» остаются быстрый старт и словарь терминов с кнопкой повторного показа обучения.
- Сетевые события не получают выдуманных оценок: все пять факторов начинают с нуля и уровня «не подтверждено», пока пользователь явно не внесет результаты собственной проверки.
- «Event Pack»: импорт от 1 до 50 событий из строгого UTF-8 JSON через системный проводник Android, без доступа ко всему накопителю.
- «Контур подлинности»: Secure Envelope v1 подписывает точные байты Event Pack алгоритмом `SHA256withRSA`, а приложение проверяет закрепленный публичный ключ, разрешенное имя источника и отпечаток подписи до разбора payload.
- Обычный Event Pack v1 остается совместимым, но явно помечается «Без подписи». После подписанного каталога приложение блокирует неподписанную замену и переход с production-ключа на development-ключ.
- «Паспорт источника»: отдельный PNG 1080 × 1350 связывает строгую схему, SHA-256 payload, подпись, ID ключа и детерминированный графический отпечаток. Подпись подтверждает происхождение байтов, но не истинность спортивных фактов.
- Контроль срока пакета, 12-символьная SHA-256-метка файла, изоляция пользовательских оценок по поставщику и автоматический возврат к восьми демо-событиям после истечения данных.
- «Радар обновлений»: квитанция между двумя версиями показывает новые, удаленные и перенесенные события, изменения оценок и уточненные поля; более старые и конфликтующие пакеты блокируются.
- Закладки, подтверждения и карта сигнала следуют за стабильным ID события между ревизиями одного источника.
- Опубликованный [контракт Event Pack v1](docs/event-pack-format.md), формальная JSON Schema и генератор свежего локального примера.
- «Часовой мост СНГ»: единый явный выбор среди 13 городов России и СНГ переводит точные даты Event Pack и известное московское демо-расписание через IANA-зоны устройства. Переход дня недели и даты показывается вместе со временем.
- Неизвестное расписание остается неизвестным, смещения UTC не зашиты вручную, выбор города хранится только локально, а расчет не требует сети или геолокации. Алгоритм и ограничения опубликованы в [спецификации «Часового моста»](docs/time-bridge.md).
- «Эстафета фактов»: автоматически сравнивает подтверждения сейчас и в точный момент старта. Пять нативных дорожек показывают, какой уровень доживет, где случится первая деградация и когда откроется безопасное окно повторной проверки.
- Проекция сначала применяет «Антиэхо», затем общую политику свежести и готовности; изменение статуса `сейчас → к старту` не является прогнозом исхода. При отсутствии точного или демо-расписания дедлайн не придумывается. Формула опубликована в [спецификации «Эстафеты фактов»](docs/evidence-relay.md).
- «Предстартовый протокол»: превращает пять дорожек в сгруппированные контрольные слоты и переносимый `.ics` с отдельным маркером старта. Будущее окно округляется только вверх, одинаковые минуты объединяются, а отсутствие подтверждения становится явным первым слотом.
- «Контур синхронизации» сравнивает текущий план с последней локальной квитанцией передачи и явно различает новый, актуальный, устаревший и поврежденный план. Перенос старта, окон, города или названия показывается до повторного экспорта и не смешивается с обычным течением минут.
- В календарь передаются UTC-моменты, выбранная IANA-зона, стабильные UID, монотонный `SEQUENCE` и две SHA-256-метки. Новая ревизия обновляет перенесенные события и помечает исчезнувшие группы факторов как `STATUS:CANCELLED`. Разрешение календаря не требуется: файл создается только по явной команде и передается выбранному приложению через read-only URI. Формат опубликован в [спецификации «Предстартового протокола»](docs/preflight-protocol.md).
- «Радар ревизий» в ленте проверяет все локальные календарные квитанции независимо от фильтра, закладки и текущего Event Pack. Он различает поврежденный, удаленный, потерявший точное время, устаревший, отозванный, актуальный и завершенный планы, а первые три проблемы поднимает в единую очередь.
- Если будущее событие исчезло из каталога или потеряло точный старт, радар создает только ревизию отмены: прежние UID сохраняются, `SEQUENCE` увеличивается, все слоты и старт получают `STATUS:CANCELLED`, а уведомления не создаются. Отзыв сохраняется локально для последующего восстановления; завершенную или нечитаемую orphan-квитанцию можно удалить отдельно, не выдавая это за изменение внешнего календаря. Правила опубликованы в [спецификации «Радара ревизий»](docs/revision-radar.md).
- «Сюжет события»: источник, факты, календарный план, решение, старт и разбор собраны в шесть последовательных глав. Лента показывает текущую главу, а Пульс — полную шкалу, состояние каждого этапа и одно точное следующее действие.
- Пульс разделен на два явных режима. «Коротко» открывается из ленты по умолчанию и показывает итог, текущую главу и компактную сводку «История и контроль»; контрольная точка, личный вопрос, маяк и полное досье раскрываются только по явной команде. «Подробно» сохраняет полный набор аналитических инструментов, но показывает только один из разделов `Маршрут / Факты / Решение`. Read-only навигатор объясняет, какой раздел логично открыть следующим; действие текущей главы само открывает нужный раздел и точный модуль без автоматического изменения данных.
- Выбранный режим хранится локально. Read-only просмотр «Сюжета» не создает отметки проверки и не расходует бюджет внимания; правила переключения опубликованы в [спецификации режимов Пульса](docs/pulse-workspaces.md).
- «Маяк события» отвечает не на вопрос «сколько осталось», а на более полезный вопрос «когда сюжет действительно изменится». На одной read-only шкале он связывает действие сейчас, ближайшее безопасное окно проверки, первое доказуемое снижение свежести, указанный старт и консервативную границу разбора.
- Маяк показывает не больше одной ближайшей точки каждого типа и не создает уведомления или историю простым просмотром. Абсолютный срок факта появляется только после реальной локальной отметки проверки; preview-время не выдается за сохраненный факт. Алгоритм опубликован в [спецификации «Маяка события»](docs/story-beacon.md).
- «Контрольная точка сюжета» по явной команде запоминает одну версию события и при возвращении показывает только изменения афиши, шести глав, маршрута, времени и «Маяка». Автоматической истории визитов и фоновой записи нет.
- Снимок и сравнение получают отдельные SHA-256-метки; поврежденная запись отклоняется fail-closed. Служебное время вычисления и техническая смена внутренних меток не создают ложный diff. Контракт опубликован в [спецификации «Контрольной точки»](docs/story-checkpoint.md).
- «Нить события» позволяет закрепить один личный вопрос к незавершенной главе: источнику, фактам, плану, решению, старту или разбору. При возвращении панель честно различает `открыт`, `сдвинулся`, `закрыт` и `упущен`, не превращая интерес в скрытый балл или серию посещений.
- На событие хранится только одна нить. Она создается, заменяется и удаляется явной командой, ничего не отслеживает в фоне, не создает уведомлений и fail-closed отклоняет поврежденную запись. Полный контракт опубликован в [спецификации «Нити события»](docs/story-thread.md).
- «Карточка нити» превращает один выбранный вопрос в фирменный PNG 1080 × 1350: событие, глава, состояния `тогда → сейчас`, статус, ближайшая опорная точка и SHA-метка. Это сфокусированный артефакт истории, а не полный аналитический отчет.
- Карточка создается только по явной команде, заново проверяет локальную нить перед рендером, атомарно записывается во внутренний кэш и передается через временный read-only URI. Оценки факторов, решение, коэффициенты и ответы ретроспективы не экспортируются. Контракт опубликован в [спецификации «Карточки нити»](docs/story-thread-card.md).
- «Карта нитей» собирает в ленте все явно выбранные вопросы: поврежденные связи, события вне текущего Event Pack, смысловые сдвиги, упущенные, открытые и закрытые нити. Для открытых вопросов показывается ближайшая связанная точка «Маяка», а команда ведет прямо в «Сюжет» нужного события.
- Порядок карты опубликован и не является скрытым рейтингом: целостность и потерянная связь → изменение → упущенный момент → ближайший открытый вопрос → закрытая нить. Простой просмотр ничего не записывает, не создает серию посещений и не запускает фоновое наблюдение. Полный контракт опубликован в [спецификации «Карты нитей»](docs/story-thread-map.md).
- «Тихое окно» выбирает самый ранний абсолютный момент среди открытых и сдвинувшихся нитей всей карты. Оно показывает точное региональное время возврата без обратного отсчета, награды за ожидание или скрытого ранжирования событий.
- Явная команда может включить необратимую паузу точно до этой точки, если она ближе 24 часов, либо до границы существующего 24-часового контракта. Карта и точка повторно вычисляются перед подтверждением и перед записью; без доказанного абсолютного времени действие не предлагается. Уведомления и фоновая задача не создаются. Полные правила опубликованы в [спецификации «Тихого окна»](docs/story-quiet-window.md).
- «Капсула возврата» атомарно запечатывает вместе с паузой один выбранный вопрос, его состояние и исходную точку. До срока результат закрыт; приложение ничего не проверяет в фоне и не показывает обратный отсчет.
- После паузы капсула различает неизменную локальную версию, перенос однотипной точки, смысловой сдвиг, закрытие, упущенный момент, потерю события, удаление и повреждение нити. 24-часовая граница не выдается за достижение более далекой точки. Капсула закрывается только явной командой, а исходная нить сохраняется. Полный контракт опубликован в [спецификации «Капсулы возврата»](docs/story-return-capsule.md).
- «Кадр возвращения» превращает открытый итог капсулы в фирменный PNG `1080 × 1350`: исходная точка, один вопрос, состояния `тогда → сейчас`, честная классификация, при необходимости новая точка и две SHA-256-метки. `SEALED` не экспортируется, а 24-часовая граница явно показывает «не вскрыто» вместо ложного достижения более дальней точки.
- Перед рендером приложение повторно читает капсулу, заново вычисляет всю read-only карту на одном `now` и создает минимальный снимок без полной строки, карты, оценок, коэффициентов или решения. PNG атомарно попадает только во внутренний кэш и передается через временный read-only URI. Контракт опубликован в [спецификации «Кадра возвращения»](docs/story-return-frame.md).
- «Маршрут фактов» соединяет две–четыре сохраненные карточки в один маршрут проверок: действие сейчас, одна ближайшая доказанная точка на событие, открытый хронологический порядок, региональное время и SHA-256. Исходы, вероятности, коэффициенты и общая выплата не вычисляются.
- Ноль, одно, допустимое и превышенное число событий имеют разные состояния. Пятое событие никогда не отбрасывается автоматически: экспорт блокируется, пока пользователь явно не изменит состав. Перед PNG приложение повторно читает закладки и пересчитывает все сюжеты и Маяки на одном `now`. Полный контракт опубликован в [спецификации «Маршрута фактов»](docs/fact-express.md).
- «Слепой раунд» на основе готового «Маршрута фактов» временно скрывает команды, спорт и регион. Выбор первой проверки опирается только на главу, действие и ближайшую доказанную точку, а раскрытие сравнивает его с открытым порядком фактов.
- Это антиякорная пауза, а не тест, прогноз или измерение bias. Совпадение и различие описательны, не создают оценку, серию или награду. Сеанс живет только в памяти диалога, защищен SHA-256 и блокируется режимом тишины. [Полный контракт](docs/blind-round.md).
- «Рентген подборки» пересчитывает от двух до восьми сохраненных событий на одном `now` и показывает матрицу `5 факторов × N событий`: где оценка укладывается в свежий предел источников, где выходит за него и где неподтвержденная часть меняет статус данных.
- Матрица сохраняет каталоговый порядок и не ранжирует команды. Главный разрыв выбирается по открытому правилу, ведет к точному событию и фактору в `LAB`, а во время паузы остается видимым без активного перехода. Состояние эфемерно, а расчет защищен SHA-256. [Полный контракт](docs/collection-xray.md).
- Маршрут не использует награды или скрытый балл. Снимок решения можно создать только строго до старта, а разбор открывается не раньше чем через четыре часа после него. Эта граница не выдается за фактический финальный свисток; правила опубликованы в [спецификации «Сюжета события»](docs/event-story.md).
- «Постер сюжета»: текущую главу, шесть состояний, одно следующее действие и временные границы можно собрать в фирменный PNG 1080 × 1350. Числовые оценки, само решение и ответы ретроспективы не экспортируются.
- Постер создается только по явной команде, атомарно хранится во внутреннем кэше и передается выбранному приложению через временный read-only URI. Контракт опубликован в [спецификации «Постера сюжета»](docs/event-story-poster.md).
- Фильтры по видам спорта и локально сохраненные события.
- Уникальный «Пульс матча»: пятифакторная карта формы, состава, нагрузки, контекста и качества источников.
- «Штаб проверки»: единая очередь связывает стоп-контракт, независимость и свежесть источников, «Контрракурс», рынки и маршрут проверки, а затем ведёт прямо к точному фактору.
- Шесть открытых уровней `СТОП → РЕМОНТ → СВЕЖЕСТЬ → ПРОВЕРКА → МАРШРУТ → КОНТРОЛЬ` полностью заменяют скрытый общий балл. Причины одного уровня и фактора объединяются, несколько рынков сворачиваются в одно действие, а первые три шага и полный результат получают SHA-256-метку. Формальные правила опубликованы в [спецификации «Штаба проверки»](docs/verification-command.md).
- «Диспетчер событий»: лента запускает «Штаб проверки» для всей выбранной области и показывает три события, которые требуют внимания раньше остальных. Четыре полосы дают точные количества `СТОП / ВНИМАНИЕ / В РАБОТЕ / СТАБИЛЬНО`.
- Межсобытийный порядок учитывает уровень причины, дедлайн и тип задачи раньше закладки или положения в каталоге. Read-only снимок не создаёт временную историю простым просмотром ленты, а SHA-256 связывает даже скрытые за первыми тремя строками события. Формальные правила опубликованы в [спецификации «Диспетчера событий»](docs/event-dispatch.md).
- «Контур дистанции»: четыре прямых вопроса об отыгрыше, деньгах, состоянии и лимитах создают явную паузу перед выводом «Факты сверены». Любой рисковый ответ сразу дает `STOP`; числового балла и скрытой модели нет.
- Только четыре «Нет» создают одноразовый допуск на 30 минут. Он нужен только для «Факты сверены», потребляется одним снимком и отзывается режимом тишины. «Пропустить» и «Наблюдать» остаются доступными, а метка использованного допуска входит в `DecisionSnapshot` начиная с v3. Правила опубликованы в [спецификации «Контура дистанции»](docs/decision-distance.md).
- «Бюджет внимания»: считает только foreground-время в режиме «Подробно» раздела «Анализ» и в «Чек-листах» в пределах московского дня. Дневной лимит выбирается от 15 до 120 минут с шагом 15; после начала анализа его можно только уменьшить до следующего дня.
- На 75% появляется явная граница, на 100% вывод «Факты сверены» закрывается, но «Пропустить» и «Наблюдать» остаются доступны. Агрегат текущего дня хранится локально без сервиса и разрешений, а SHA-256-метка входит в `DecisionSnapshot` v4. Правила опубликованы в [спецификации «Бюджета внимания»](docs/attention-budget.md).
- «Бортовой журнал»: каждое сохранение решения становится новым звеном с номером, временем, событием, выводом, SHA-256 снимка и меткой предыдущего звена. Повторное решение по одному событию не стирает раннюю запись.
- Журнал атомарно записывается вместе со снимком, хранит проверяемое окно последних 50 звеньев и переносит удаленную границу в криптографический якорь. Подмена, перестановка или повреждение fail-closed блокируют новые записи до явного сброса; квитанцию можно отправить через Android Share. Формальные ограничения опубликованы в [спецификации «Бортового журнала»](docs/decision-ledger.md).
- «Кворум фактов»: неподтвержденная шкала учитывается максимум на 25 баллов, один источник на 60, два независимых источника на 100.
- «Срок факта» в коротком режиме и «Реестре фактов» отдельно показывает сохранённое происхождение и текущую силу доказательства. Форма действует этапами по 72 часа, состав — 6, нагрузка — 24, контекст — 48, источники — 12; кворум сначала ослабевает `2+ → 1`, затем истекает.
- Счётчик «свежий кворум» и «Факт-маршрут» используют текущий уровень: истёкший фактор перестаёт считаться готовым и становится приоритетной перепроверкой, а последнее 25-процентное окно предупреждает об обновлении заранее. Расчёт read-only, без таймера и фонового сервиса; формальный контракт опубликован в [спецификации «Реестра фактов»](docs/fact-register.md).
- «Единый срез» обнаруживает более тонкий риск: факты могут быть индивидуально свежими, но собранными в разные моменты. Пятидорожечная шкала сравнивает `checkedAt`, использует открытое окно в 25% срока самого быстрого активного фактора и при разрыве называет старейшую квитанцию. [Формальный контракт](docs/fact-time-slice.md).
- Когда все пять свежих кворумов готовы, но относятся к разным моментам, отдельная команда открывает старейший факт и возвращает в пересчитанный реестр. При повреждении, конфликте, истечении или пропуске основной маршрут сохраняет приоритет; скрытого балла и фонового обновления нет.
- «Антиэхо источников»: заявленные `2+` не становятся кворумом без отдельного аудита происхождения. Неизвестная или общая первичная цепочка учитывается как один источник, а существенное расхождение — как неподтвержденный фактор.
- Пять каналов «заявлено → учтено» показывают влияние аудита до расчета свежести, тени, маршрута, стресс-теста, стоп-контракта и рынков. Ручная проверка получает детерминированную SHA-256-метку; правила опубликованы в [спецификации «Антиэхо»](docs/source-integrity.md).
- «Контрракурс»: пользователь отдельно проверяет альтернативную трактовку формы, состава, нагрузки, контекста и источников. Меньше трех проверок или контрфакт ограничивают вывод до «пропустить», незавершенная или спорная картина — до «наблюдать».
- Контур не меняет числовую готовность и никогда ее не повышает. Он блокирует сохранение вывода выше честного потолка, входит в пломбу снимка решения и автоматически запускает стоп-контракт при последующем споре или контрфакте. Открытые правила опубликованы в [спецификации «Контрракурс»](docs/counter-view.md).
- «Дуэль данных»: два события сравниваются по шести открытым дорожкам — готовности, чистоте сигнала, свежему кворуму, независимости источников, контрпроверке и запасу срока. Команды, коэффициенты и вероятность исхода в расчет не входят.
- Каждая дорожка имеет одинаковый вес, ничьи показываются отдельно, а общий скрытый рейтинг отсутствует. Потолки «Контрракурса» остаются отдельными, выбор правого события сохраняется локально, а сравнение получает SHA-256-метку. Формальные правила опубликованы в [спецификации «Дуэль данных»](docs/data-duel.md).
- «Хронолинза»: интерактивный ползунок строит единый будущий срез готовности, пяти сроков подтверждения, рынков, потолка «Контрракурса» и стоп-контракта без изменения текущих данных.
- Открытые границы показывают окно истечения на 75% срока и точные переходы `2+ → 1 → 0`. Горизонт ограничен 24–144 часами, смоделированное нарушение не защелкивается, а каждый срез получает SHA-256-метку. Формальные правила опубликованы в [спецификации «Хронолинзы»](docs/chrono-lens.md).
- «Срок жизни сигнала»: у каждого фактора собственный период актуальности от 6 до 72 часов; просроченное подтверждение автоматически теряет уровень и снижает итоговую готовность.
- «Маршрут проверки»: точный перебор всех комбинаций факторов находит минимальный набор кворумов до следующего статуса или доказывает, что дополнительные источники его не изменят.
- «Честный предел»: приложение показывает максимум текущих фактов и прямо отделяет необходимость новых данных от желания повысить уверенность.
- «Стресс-тест сигнала»: по очереди снимает один уровень подтверждения с каждого фактора, находит единственный критический сбой и показывает, сохранится ли текущий статус.
- Временная кривая без случайных вероятностей моделирует все будущие сроки подтверждений и называет точный фактор и момент, когда статус изменится без обновления данных.
- «Тень уверенности»: янтарный пунктир показывает исходную оценку, бирюзовый контур — часть, которую выдерживают свежие источники; приложение называет главный разрыв и отдельно предупреждает, если он меняет статус.
- Статус тени не использует произвольную вероятность: он сравнивает фактические вердикты до и после доказательных ограничений, а критический фактор выбирается по реальному влиянию на готовность.
- «Коридор решения»: полный перебор значений каждого фактора находит минимальное изменение до соседнего статуса в обе стороны и показывает первую точку перехода.
- Пробный контрсценарий не меняет сохраненную карту; если лимиты источников не позволяют пересечь границу одним фактором, приложение сообщает это прямо.
- «След решения»: журнал замораживает исходные оценки, уровни подтверждения и время проверки, а затем показывает дельту готовности без пересчета прошлого задним числом.
- Причины изменений разделены на новые факты, обновление подтверждения и потерю свежести; неизменившаяся карта не создает ложную дельту.
- Каждый снимок получает локальную контрольную метку SHA-256, которая связывает экран, журнал и PNG-паспорт. Это маркер целостности локальных данных, а не электронная подпись.
- «Стоп-контракт»: в момент сохранения решения приложение заранее вычисляет критический фактор, первую стоп-линию до недопустимого статуса и минимальный уровень его подтверждения.
- Контракт автоматически срабатывает при пересечении стоп-линии, падении подтвержденного статуса или потере запечатанного кворума. Вывод выше фактического сигнала блокируется уже в момент фиксации.
- Первое обнаруженное нарушение защелкивается с отдельной SHA-256-меткой: восстановление шкал не чинит старую пломбу и не скрывает момент срабатывания. Снять защелку может только новый снимок решения.
- Решение «пропустить» запечатывается отдельно и не повышается задним числом при движении шкал. Новый вывод требует нового снимка.
- Условие связано со снимком отдельной SHA-256-пломбой и экспортируется в PNG 1080 × 1350. Формальный алгоритм без скрытой вероятности опубликован в [спецификации «Стоп-контракт»](docs/decision-guard.md).
- «Линза рынков»: интерактивная матрица связывает шесть шаблонов рынка с пятью эффективными факторами текущего события и показывает, где данных достаточно, где нужна проверка, а где критический блокер закрывает анализ.
- Применимость зависит от вида спорта. Статус чек-листа требует хотя бы одного источника по обязательным факторам и свежей независимой сверки критических факторов; ручные баллы не открывают и не закрывают чек-лист. Формальные правила опубликованы в [спецификации «Линза рынков»](docs/market-lens.md).
- Следующая проверка выбирается детерминированно и открывает конкретный фактор в «Пульсе», не изменяя пользовательскую карту или журнал решения.
- Служебный планировщик сравнивает пять проверок и выбирает одну с максимальным доказательным эффектом для применимых чек-листов. В основной интерфейс контрсценарии не выводятся.
- Контрсценарий использует только открытую границу `60 + свежий кворум`, не записывается в состояние и показывает шесть мини-карт «сейчас → после проверки». Если матрица уже покрыта, функция находит ближайшую общую точку обновления свежести.
- «После свистка»: постсобытийный аудит проверяет форму, состав, нагрузку, контекст и источники без ввода счета, коэффициентов, выигрыша или проигрыша.
- Прозрачная калибровка процесса: подтвержденный фактор получает 100, частичный 50, опровергнутый 0, а «нет данных» не искажает среднее; итог показывается только при трех проверяемых факторах.
- «Ложная уверенность» выявляется отдельно, если фактор с кворумом источников и значимой исходной оценкой оказался неверным.
- Черновик переживает перезапуск, завершенная ретроспектива закрывает решение и связывает две SHA-256-метки в отдельном PNG-разборе. Полная методика опубликована в [спецификации «После свистка»](docs/post-event-review.md).
- «Память процесса» объединяет только завершенные и связанные с исходными решениями ретроспективы, считает покрытие проверяемых факторов и строит общую карту до шести последних разборов.
- Повторяющийся фактор ниже 45/100 не может скрыться за высоким общим средним: после двух наблюдений он становится отдельной слепой зоной и фокусом следующей проверки.
- Тренд сравнивает две предыдущие и две последние ретроспективы, а детерминированная SHA-256-цепочка связывает всю серию. Профиль можно передать как отдельный PNG 1080 × 1350 без счета, коэффициентов и финансового результата.
- Шумометр и три честных состояния: «пропустить», «наблюдать», «факты сверены».
- Журнал решения, который фиксирует вывод и время до просмотра новых мнений.
- «Паспорт события»: экспорт подтвержденного разбора, результатов «Антиэхо» и «Контрракурса» с контрольными метками в фирменный PNG 1080 × 1350 с временной отметкой и ответственным дисклеймером. Название матча, турнир и регион адаптивно помещаются до трёх строк без многоточия.
- Интерактивный чек-лист с сохранением прогресса.
- Справочник рынков с отдельным стоп-сигналом для каждого типа.
- «Режим тишины» до явно подтвержденной точки или максимум на 24 часа, блокирующий новые решения и изменение локального состояния.
- Собственные визуальные материалы без логотипов команд, букмекеров и казино.

## Локальные данные

«Протокол проверки» вычисляется при открытии из текущего главного пробела, уровня доказательств и свежести. Просмотр шагов и SHA-256-метки ничего не записывает; локальное состояние меняется только после явного перехода в форму и действия пользователя.

Для каждого события и фактора может храниться одна «Факт-квитанция»: тезис, до двух введённых пользователем обозначений источников, их связь, полнота, время и SHA-256-пломба. Приложение не открывает и не отправляет введённые ссылки. Сохранение атомарно обновляет только оценку, заявленный уровень, время и антиэхо этого фактора; ручное изменение любого из этих полей отвязывает старую квитанцию. Удаление явно сбрасывает фактор к исходным данным события.

«Реестр фактов», «Срок факта», «Единый срез» и «Кросс-эхо» не хранятся отдельно и не копируют квитанции. При каждом открытии они заново выводят пять строк, текущие этапы свежести, временной разброс, следующий фактор, нормализованную карту происхождений и три SHA-256-метки из текущих локальных записей и одного текущего времени.

«Факт-маршрут» также не сохраняет очередь или текущий шаг. Возврат из редактора просто открывает заново вычисленный реестр, поэтому маршрут всегда отражает фактически сохранённые квитанции.

Для каждого события может храниться одна локальная квитанция последнего успешно запущенного сценария передачи предстартового `.ics`: активного плана или его отзыва. Она нужна для глобального контроля расписания и продолжения `SEQUENCE`, но не подтверждает выбор приложения, доставку файла, завершенный импорт или применение отмены и не образует историю экспортов.

Для каждого события также может храниться одна «Контрольная точка сюжета». Она создается, заменяется или удаляется только явной командой; обычный просмотр не записывается как визит и не образует историю версий.

Для каждого события может храниться одна «Нить события»: выбранная глава, ее исходное состояние, время закрепления и SHA-256-пломба. Текущее состояние вычисляется при открытии, не сохраняется как история и не проверяется фоновым сервисом.

«Карта нитей» не создает отдельного профиля или копию вопросов. Она read-only перечисляет существующие локальные нити, заново вычисляет статус только для событий текущего каталога и сохраняет потерянную связь видимой после замены Event Pack. Удаление такой связи выполняется только явной командой и блокируется режимом тишины.

«Тихое окно» также не создает отдельного профиля: результат каждый раз выводится из текущей «Карты нитей» и текущего времени. Только подтвержденная команда атомарно записывает существующий глобальный `pause_until` и одну минимальную «Капсулу возврата» с исходной пломбой выбранной нити и точки; одноразовый допуск «Контура дистанции» очищается, уведомление и фоновая задача не создаются.

«Капсула возврата» не хранит историю пауз или промежуточных состояний. После срока она сравнивается с текущей read-only картой только при открытии приложения. Явное закрытие удаляет капсулу, но не исходную «Нить события» и не истекший служебный срок паузы.

«Кадр возвращения» не создает новую постоянную запись. Его минимальный снимок существует только в памяти на время рендера, а PNG временно хранится в общем закрытом кэше экспортов. Повторное создание перечитывает капсулу и карту, поэтому не использует устаревший результат панели.

«Маршрут фактов» также не создает отдельный набор или историю. Его состав каждый раз выводится из закладок текущего каталога, а сюжет, ближайшая точка, порядок и SHA-256 пересчитываются на одном `now`. Только явная команда создает временный PNG в общем закрытом кэше экспортов.

«Слепой раунд» не создает постоянного состояния. Анонимные карточки, выбор и раскрытие существуют только в памяти открытого диалога; закрытие удаляет их без истории, профиля или экспорта.

«Рентген подборки» также не создает набор, профиль или историю. Состав берется из текущих закладок, а аудит источников, свежесть, доказательный предел, матрица, главный разрыв и SHA-256 заново вычисляются в памяти на одном `now`. Просмотр и переход не подтверждают фактор и не меняют исходные данные.

«Карточка нити» не создает новую постоянную запись. PNG временно появляется во внутреннем кэше только после явной команды, а выбранное приложение получает доступ на чтение только к конкретному файлу через Android Share.

Выбранное событие, режимы Ленты и Пульса, город «Часового моста», правое событие «Дуэли данных», две последние версии Event Pack или подписанного envelope, квитанция их сравнения, шкалы, уровни подтверждения, аудит независимости, пять состояний «Контрракурса», время последней проверки факторов, выбранная строка «Линзы рынков», сохраненные карточки, чек-лист, журнал, неизменяемые снимки решений, первая защелкнутая запись нарушения стоп-контракта, черновик и финальная ретроспектива «После свистка», пауза, одна «Капсула возврата», дневной лимит внимания и суммарное время текущего московского дня хранятся только в `SharedPreferences` на устройстве и исключены из резервного копирования. Результат «Сюжета события», «Предстартового протокола», «Эстафеты фактов», «Дуэли данных», «Штаб проверки», «Диспетчер событий», план «Стоп-контракта» и матрица рынков детерминированно восстанавливаются из текущих локальных данных, а положение и результат «Хронолинзы» вместе с контрсценариями «Фактора-рычага» существуют только в памяти и никогда не записываются. Бюджет внимания обновляется только при активном экране приложения в режиме «Подробно» или разделе «Рынки»; фонового сервиса и истории по дням нет. Read-only снимок сюжета, диспетчера, «Эстафеты фактов», «Предстартового протокола» и расчет часовых зон не создают отсутствующие отметки времени. Смоделированное нарушение «Хронолинзы» не защелкивается. Реальное нарушение записывается только при открытии текущего анализа; фонового мониторинга и скрытого профиля нет. «Память процесса» вычисляется локально из завершенных ретроспектив и не создаёт отдельного профиля пользователя. JSON сохраняется в Base64 без изменения исходных байтов, поэтому SHA-256 и криптографическая подпись повторно проверяются после перезапуска. Системный проводник предоставляет приложению доступ только к выбранному JSON, который затем копируется в закрытое хранилище. Созданные паспорта и `.ics` временно сохраняются во внутреннем кэше; при отправке выбранное приложение получает read-only доступ только к конкретному файлу. Приложение использует только разрешение `INTERNET` для HTTPS-загрузки расписания и не запрашивает доступ к календарю, аккаунту, геолокации, платежным данным или всему накопителю.

«Бортовой журнал» хранит в тех же закрытых `SharedPreferences` не больше 50 последних фиксаций с якорем ротации. Просмотр ничего не записывает; явный сброс удаляет только цепочку, а текстовая квитанция передается выбранному приложению через стандартный Android Share.

«Контур дистанции» не хранит черновик ответов или неуспешные самопроверки. В `SharedPreferences` может попасть только срок и SHA-256-метка успешного all-clear допуска; он отзывается паузой, исчезает после одного сильного вывода или fail-closed игнорируется после истечения 30 минут.

## Сборка

Требуются Android SDK 36 и JDK 17.

Для debug и release задаётся только публичный HTTPS endpoint серверного шлюза:

```properties
SPORTS_SCHEDULE_PROXY_URL=https://schedule.example.ru/fixtures
```

Ни одна APK-сборка не содержит ключ провайдера и не принимает прямой URL API-Sports. Секрет хранится только на сервере. Полная схема подключения, кеширования и ошибок описана в [документе защищённого подключения](docs/api-sports.md).

Серверный шлюз запускается на Node.js 20 после того, как `API_SPORTS_KEY` добавлен через secret manager платформы:

```bash
cd server
npm start
```

```bash
./gradlew :app:testDebugUnitTest :app:lintDebug :app:assembleDebug
```

Debug APK появится в `app/build/outputs/apk/debug/app-debug.apk`.
