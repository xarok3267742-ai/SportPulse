# Защищённое подключение спортивного расписания

## Назначение

Приложение загружает футбольное расписание на текущую московскую дату и два следующих дня. В каталог попадают события России, Беларуси, Казахстана, Армении, Азербайджана, Кыргызстана, Узбекистана, Таджикистана, Туркменистана и Молдовы. После сортировки и удаления дублей показывается не больше 60 ближайших событий.

Источник подтверждает только поля расписания: турнир, команды, время, статус и доступный счёт. Он не подтверждает форму, состав, нагрузку, независимость источников или пользовательский вывод. Поэтому каждое новое сетевое событие начинается с нулевых оценок и уровня `UNCONFIRMED`.

## Граница безопасности

Android-приложение никогда не хранит и не отправляет ключ API-Sports. Это правило одинаково для debug и release. Обфускация, ресурсы, `BuildConfig`, `local.properties` и Android Keystore не превращают общий ключ провайдера в безопасный клиентский секрет.

Единственная разрешённая схема:

```text
Android APK -> HTTPS proxy -> API-Sports
               секрет здесь
```

Прямые домены API-Sports и API-Football через RapidAPI блокируются и при сборке, и в runtime. URL с HTTP, встроенными credentials или fragment также отклоняется.

Ключ, который когда-либо передавался в чат, журнал или debug APK, нужно отозвать и выпустить заново перед настройкой proxy.

## Настройка Android

Приложению передаётся только публичный HTTPS endpoint proxy. Его можно задать Gradle property, переменной окружения или в игнорируемом Git-файле `local.properties`:

```properties
SPORTS_SCHEDULE_PROXY_URL=https://schedule.example.ru/fixtures
```

Если URL не задан, приложение безопасно переходит на демонстрационный каталог. В пользовательском интерфейсе не показываются URL, имя провайдера, ключ, квота или детали серверной конфигурации.

## Контракт proxy

Android выполняет `GET` и добавляет два параметра:

```text
GET /fixtures?date=2026-08-07&timezone=Europe%2FMoscow
Accept: application/json
```

Proxy должен:

1. Хранить `API_SPORTS_KEY` только в серверном secret manager или переменной окружения.
2. Разрешать только `GET`, валидную дату в рабочем окне и `Europe/Moscow`.
3. Ограничивать частоту запросов и кешировать ответ по дате.
4. Отправлять ключ провайдеру на серверной стороне.
5. Не возвращать ключ, upstream request headers, quota headers или внутренние ошибки.
6. Возвращать совместимый JSON envelope с `parameters`, `errors` и `response`.
7. Ограничивать размер и поля ответа до данных, нужных приложению.

Публичный proxy всё равно требует защиты от злоупотреблений. Для production нужны rate limit, серверный кеш, мониторинг и, при необходимости, проверка Play Integrity. Нельзя заменять серверный secret вторым статическим ключом внутри APK.

Готовая dependency-free реализация для Node.js 20 находится в `server/server.mjs`. Она валидирует трёхдневное окно, ограничивает частоту, кеширует ответы на пять минут и удаляет лишние поля. Перед production-развёртыванием постоянный rate limit и мониторинг нужно вынести в инфраструктуру платформы.

## Сеть и кеш

- Выполняются три `GET`-запроса: по одному на каждую дату трёхдневного окна.
- Часовой пояс запроса: `Europe/Moscow`.
- Автоматическое обновление не выполняется, пока кеш моложе 6 часов.
- Ручное обновление ограничено одним разом в час.
- Последний корректный кеш хранится до 48 часов и остаётся доступным при сетевой ошибке.
- Ошибки внутри HTTP 200 проверяются по полю `errors`; повреждённый ответ не заменяет корректный кеш.
- HTTP 401/403 и 429 преобразуются в нетехнические пользовательские состояния.
- Кеш записывается атомарно во внутреннее хранилище приложения.

## Приоритет источников

1. Свежий импортированный Event Pack.
2. Непустое онлайн-расписание.
3. Встроенный демонстрационный каталог.

Истёкший Event Pack не блокирует онлайн-расписание. На экране «Источник событий» видны только тип источника, время обновления и окно дат.
