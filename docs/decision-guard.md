# Стоп-контракт v1

«Стоп-контракт» заранее фиксирует условие, при котором сохраненный вывод больше нельзя использовать. Это локальный механизм дисциплины решения, а не прогноз результата события.

## Исходные данные

Контракт строится только из неизменяемого `DecisionSnapshot`:

- выбранный вывод: `SKIP`, `OBSERVE` или `DATA_READY`;
- пять исходных оценок от 0 до 100;
- уровни подтверждения каждого фактора;
- время последней проверки подтверждений;
- пять состояний «Контрракурса»;
- SHA-256-метка снимка.

Текущая карта не изменяет исходный контракт. Она используется только для проверки заранее зафиксированных условий.

## Требуемый статус

Выбранный вывод однозначно переводится в минимальный статус сигнала:

| Вывод | Минимальный статус |
| --- | --- |
| `SKIP` | `SKIP` |
| `OBSERVE` | `OBSERVE` |
| `DATA_READY` | `READY` |

Если подтвержденный статус уже в момент сохранения ниже выбранного вывода, контракт сразу получает причину `DECISION_ABOVE_SIGNAL`.

## Стоп-линия

Для `OBSERVE` и `DATA_READY` движок перебирает каждый фактор в стабильном порядке:

1. Значение фактора уменьшается по одному пункту.
2. Остальные четыре значения и уровни подтверждения остаются неизменными.
3. Первое значение, при котором статус становится ниже требуемого, считается стоп-линией фактора.
4. Из найденных линий выбирается минимальное изменение; при равенстве побеждает более ранний фактор в порядке `FORM`, `LINEUP`, `LOAD`, `CONTEXT`, `SOURCES`.

Контракт запечатывает исходное значение выбранного фактора, его стоп-линию и действующий уровень подтверждения. Если один фактор не может понизить требуемый статус, выбирается фактор с наибольшей потерей готовности при ослаблении подтверждения. При полном отсутствии подтверждений используется самый слабый фактор сигнала.

## Срабатывание

Для выводов `OBSERVE` и `DATA_READY` контракт срабатывает при любом условии:

- текущий подтвержденный статус ниже зафиксированного;
- критический фактор равен стоп-линии или находится ниже нее;
- действующий уровень подтверждения критического фактора стал слабее запечатанного;
- выбранный вывод изначально был выше подтвержденного статуса.
- текущий или исходный «Контрракурс» допускает вывод ниже сохраненного решения.

Причины не взаимоисключающие и выводятся вместе. Пока нарушение не наблюдалось, обновление источника или времени проверки сохраняет контракт активным, если требуемый уровень подтверждения восстановлен.

Последнее условие записывается как `COUNTERVIEW_LIMIT`. Числовая готовность при этом может не измениться: срабатывает именно заранее зафиксированный предел альтернативной проверки.

Первое обнаруженное нарушение защелкивается локально вместе со временем, причинами, значением критического фактора, уровнем подтверждения, готовностью и статусом в момент срабатывания. Последующее восстановление шкал не чинит старую пломбу и не скрывает факт нарушения. Снять защелку можно только новым снимком решения, который получит другую пломбу.

`SKIP` обрабатывается отдельно: пропуск запечатывается и не повышается автоматически при изменении шкал. Для другого вывода требуется новый снимок решения.

## Локальная пломба

Пломба вычисляется как SHA-256 от канонической строки:

```text
sport-pulse-decision-guard-v1
eventId
armedAt
decision
requiredVerdict
factor
baselineValue
scoreFloor
requiredEvidence
evidenceValidUntil
snapshotFingerprint
```

Поля объединяются символом `|`. Пустые необязательные поля остаются пустыми. Пломба связывает контракт с конкретным снимком, но не является электронной подписью и не подтверждает истинность спортивных данных.

Запись первого нарушения получает собственную SHA-256-метку и принимается только вместе с совпадающей полной пломбой контракта. Поврежденная или относящаяся к другому снимку запись игнорируется.

- короткую пломбу и метку исходного снимка;
- критический фактор, исходное значение и стоп-линию;
- минимальный уровень подтверждения;
- исходную и текущую готовность;
- состояние контракта и причины срабатывания;
- обязательный дисклеймер 18+.

Счет, коэффициенты, размер ставки, выигрыш и проигрыш в контракт не входят.
