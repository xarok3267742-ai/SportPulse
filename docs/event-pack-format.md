# Sport Pulse Event Pack v1

Event Pack — переносимый JSON-контракт для краткоживущего каталога событий. Пользователь выбирает файл через системный проводник Android, после чего приложение копирует проверенный JSON в закрытое локальное хранилище. Доступ ко всему накопителю и сетевое разрешение не нужны.

Формальные структурные схемы: [`event-pack.schema.json`](event-pack.schema.json) для payload и [`event-pack-envelope.schema.json`](event-pack-envelope.schema.json) для подписанного конверта.

## Корневые поля

| Поле | Формат | Правило |
| --- | --- | --- |
| `schemaVersion` | integer | Только `1` |
| `packageId` | string | `A-Z`, `a-z`, `0-9`, `_`, `-`; 3–64 символа |
| `source` | string | Заявленное имя источника; 2–80 символов |
| `generatedAt` | integer | Unix time в миллисекундах |
| `validUntil` | integer | Unix time в миллисекундах |
| `events` | array | От 1 до 50 событий |

`validUntil` должен быть позже `generatedAt`, а срок пакета не может превышать семь суток. Время генерации допускает не более 15 минут будущего рассогласования. При импорте просроченный пакет отклоняется; ранее сохраненный пакет после истечения автоматически уступает место демо-каталогу.

Для последовательных версий одного источника `generatedAt` должен монотонно увеличиваться. Приложение отклоняет пакет, который старше текущей версии, и конфликтующие файлы с одинаковым временем выпуска. Это защищает локальный каталог от случайного или намеренного отката.

## Событие

Каждое событие содержит `id`, `sport`, `tournament`, `region`, `match`, `startAt`, `focus`, `note`, `tags` и `assessment`. Неизвестные поля отклоняются. ID внутри пакета уникальны, а `startAt` находится в диапазоне от суток до генерации пакета до 30 суток после нее. Поставщик сохраняет один `id` за тем же событием в следующих ревизиях: так закладки и пользовательская карта продолжают работать после обновления.

`assessment` содержит пять целых оценок от 0 до 100:

- `form` — форма;
- `lineup` — состав;
- `load` — нагрузка;
- `context` — контекст;
- `sources` — качество источников.

Это стартовая редакторская оценка, а не вероятность исхода. Пользовательская проверка источников, свежесть и кворум применяются отдельно внутри приложения.

## Пример

```json
{
  "schemaVersion": 1,
  "packageId": "provider_week_31",
  "source": "Название поставщика",
  "generatedAt": 1785326400000,
  "validUntil": 1785412800000,
  "events": [
    {
      "id": "football_match_101",
      "sport": "Футбол",
      "tournament": "Национальная лига",
      "region": "Россия",
      "match": "Команда А — Команда Б",
      "startAt": 1785351600000,
      "focus": "Составы, нагрузка, темп",
      "note": "Проверьте официальные заявки перед событием.",
      "tags": ["лига", "вечер"],
      "assessment": {
        "form": 62,
        "lineup": 38,
        "load": 58,
        "context": 70,
        "sources": 46
      }
    }
  ]
}
```

Для локальной проверки можно создать пакет с актуальными временными метками:

```bash
node tools/create-demo-event-pack.mjs > /tmp/sport-pulse-event-pack.json
```

Генератор также создает вторую версию с переносом, измененными оценками, удаленным и новым событием, а также свежий пакет для проверки защиты от отката:

```bash
node tools/create-demo-event-pack.mjs --update > /tmp/sport-pulse-update.json
node tools/create-demo-event-pack.mjs --rollback > /tmp/sport-pulse-rollback.json
```

## Secure Envelope v1

Подписанный документ не канонизирует и не пересобирает Event Pack. Исходный UTF-8 JSON кодируется Base64 как `payload`, а подпись рассчитывается по точным байтам. Поэтому пробел, перевод строки или изменение одного балла делают старую подпись недействительной.

| Поле | Правило |
| --- | --- |
| `envelopeVersion` | Только `1` |
| `keyId` | ID закрепленного публичного ключа, 3–64 символа |
| `algorithm` | Только `SHA256withRSA` |
| `payloadEncoding` | Только `base64` |
| `payload` | Точные байты Event Pack v1, максимум 256 КБ |
| `signature` | RSA-подпись в Base64, от 128 до 512 байт после декодирования |

Вход подписи строится без разделителей переменной формы:

```text
SPORT_PULSE_EVENT_PACK_ENVELOPE_V1\n
<keyId>\n
SHA256withRSA\n
<точные байты payload>
```

Префикс, `keyId` и алгоритм входят в подпись. После криптографической проверки приложение разбирает payload по строгой схеме v1 и отдельно проверяет, что ключ разрешен именно для заявленного поля `source`.

Локальный development-envelope создается так:

```bash
node tools/create-demo-event-pack.mjs \
  --signed \
  --private-key .local/event-pack-dev-private.pem \
  > /tmp/sport-pulse-signed-event-pack.json
```

`.local/` исключен из Git. В приложение встроен только публичный ключ. Локальный ключ помечается «Демо-подпись» и не выдается за ключ лицензированного поставщика. Производственный порядок выпуска и ротации описан в [`source-signing-runbook.md`](source-signing-runbook.md).

Общий лимит JSON-документа с Base64-конвертом — 384 КБ. Неизвестный ключ, иной алгоритм, лишнее поле, некорректный Base64, несовпадающее имя источника и любая ошибка подписи приводят к полному отклонению файла без перехода в режим «без подписи».

## Радар обновлений

Приложение хранит текущую и непосредственно предыдущую проверенные версии. После нового импорта «Радар обновлений» детерминированно показывает:

- новые и удаленные события;
- переносы времени;
- изменения каждой из пяти стартовых оценок;
- уточнения названия, турнира, региона, фокуса, заметки и тегов;
- смену заявленного источника как полную замену каталога;
- переход между двумя SHA-256-метками.

Повторный импорт идентичного файла не стирает последнюю квитанцию. История ограничена двумя версиями и остается только на устройстве. Исходный UTF-8 JSON или secure-envelope сохраняется в Base64 без изменения байтов, поэтому контрольная метка и подпись повторно проверяются между запусками приложения.

Переход от обычного файла к подписанной копии того же payload считается обновлением доверия. Обратный переход блокируется. Production-ключ нельзя заменить development-ключом; для явного отказа от подписанного источника пользователь сначала возвращается к демо-каталогу.

## Проверка и доверие

Приложение проверяет размер, строгий UTF-8, типы, обязательные поля, длины строк, управляющие символы, временные границы, уникальность ID и тегов, диапазоны оценок и неизвестные поля.

Для обычного Event Pack показывается сокращенная SHA-256-метка точного локального содержимого. Она помогает отличить версии, но не подтверждает автора, поэтому интерфейс явно пишет «Без подписи».

Для Secure Envelope приложение до разбора payload проверяет подпись по закрепленному публичному ключу, связь ключа с именем источника и отпечаток подписи. Это подтверждает происхождение неизмененных байтов от владельца соответствующего приватного ключа. Подпись не доказывает истинность расписания, составов или оценок; для реальных данных по-прежнему нужен лицензированный поставщик и редакционный контроль.
