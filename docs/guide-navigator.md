# Навигатор проверки

«Навигатор проверки» — первый блок раздела «Гид». Он не показывает общий список возможностей, а вычисляет одно следующее действие для выбранного события по фактическому состоянию локального процесса.

## Задача

Пользователь не должен сам искать, какой экран открыть после выбора матча. Навигатор связывает пять обязательных этапов:

1. выбрать событие;
2. заполнить три вопроса плана;
3. сохранить хотя бы один проверяемый факт;
4. зафиксировать решение до события;
5. завершить связанный постсобытийный разбор.

Карточка всегда показывает текущий этап, число завершённых шагов, выбранное событие, объяснение «Почему сейчас» и одну команду. Справка, словарь и полное обучение вынесены в отдельный блок и не конкурируют с текущим действием.

## Детерминированные состояния

| Состояние | Условие | Действие |
| --- | --- | --- |
| `EVENT` | выбранного события нет | открыть «Матчи» |
| `PLAN` | отсутствует хотя бы один из трёх ответов | открыть первое незаполненное поле и передать ему фокус |
| `FACT` | план готов, но нет валидной факт-квитанции | открыть вычисленный слабый фактор |
| `DECISION` | есть план и факт, но нет снимка решения | перейти к отдельной фиксации решения |
| `REVIEW` | снимок решения сохранён | открыть «После свистка» для того же события |
| `COMPLETE` | связанный разбор завершён | открыть «Профиль проверки» |

Сохранённый снимок решения имеет приоритет над последующими изменениями черновика и фактов. Поэтому после фиксации навигатор не возвращает пользователя к редактированию исходного плана, а ведёт к связанному разбору.

## Граница смысла

Навигатор не рассчитывает вероятность исхода, коэффициент, ожидаемую доходность, размер ставки или рейтинг события. Он оценивает только наличие локальных записей процесса. Текст под действием сообщает эту границу непосредственно на экране.

Выбор шага не отправляется на сервер и не создаёт профиль пользователя. Источниками состояния служат выбранный ID события, черновик трёх вопросов, валидные факт-квитанции, снимок решения и финализированный разбор.

## Визуальная модель

Image-заголовок показывает пять физических объектов в том же порядке: событие, план, источник, запечатанное решение и разбор. Центральный указатель направлен на проверку источника, янтарная метка обозначает внимание, красная насечка — стоп-границу. Изображение не содержит текста, денег, коэффициентов, счёта или обещания результата; этап, название и команда остаются нативными Android-элементами.

При `fontScale >= 1.3` строка маршрута перестраивается вертикально. При 200% image-заголовок получает дополнительную высоту, а его нативный заголовок ограничивает только собственный масштаб внутри фиксированного кадра. Название события, объяснение и кнопка растут по содержимому без многоточия.

## Справка по запросу

«Быстрый старт» и «Словарь терминов» открываются в отдельных прокручиваемых диалогах. Команда «Закрыть» находится вне прокрутки и остаётся полностью видимой при 100% и 200% системного шрифта. В быстром старте один шаг содержит одно короткое действие; при крупном тексте номер и заголовок образуют отдельную строку, а пояснение получает полную ширину.

## Проверка

`GuideNavigatorTest` проходит все шесть состояний, проверяет порядок незаполненных вопросов, выбор слабого фактора и приоритет сохранённого решения.

`GuideNavigatorInstrumentationTest` проверяет реальное стартовое состояние, точный переход и фокус первого вопроса, содержимое двух справочных диалогов и полную видимость закреплённой команды «Закрыть». Сценарий выполняется при системном шрифте 100% и 200%.

`TextLayoutInstrumentationTest` дополнительно включает экран «Гид» в общий аудит обрезки, переполнения, многоточий и accessibility-описания image-заголовка.
