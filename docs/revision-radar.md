# Радар ревизий

«Радар ревизий» контролирует календарные планы, уже переданные из приложения. Он отвечает на вопрос «не остался ли во внешнем календаре план, который больше не соответствует текущему каталогу», а не оценивает команды, коэффициенты или вероятность исхода.

## Глобальная область

Радар читает все локальные квитанции `preflight_export_receipt_*` и весь активный каталог. Его область намеренно не зависит от фильтра вида спорта, закладок и выбранного события: скрытие строки ленты не должно скрывать потенциально устаревший календарный план.

Если квитанций нет, панель не показывается. Просмотр панели ничего не записывает, не запускает фоновую задачу и не обращается к календарю.

## Состояния

| Состояние | Условие | Действие |
| --- | --- | --- |
| `TAMPERED` | квитанция не проходит строгий разбор и SHA-256-проверку | открыть текущее событие и начать новую цепочку; orphan-квитанцию можно только удалить локально |
| `REMOVED` | будущее событие отсутствует в активном каталоге | передать ревизию отмены |
| `UNRESOLVED` | событие есть, но будущий точный старт больше недоступен | передать ревизию отмены |
| `STALE` | текущий seal расписания отличается от квитанции | открыть событие и передать обновленную ревизию |
| `WITHDRAWN` | последняя локальная ревизия является отзывом | при возврате события открыть его и восстановить план; вне каталога только наблюдать |
| `CURRENT` | текущий seal совпадает с активной квитанцией | открыть событие или повторно передать тот же план |
| `EXPIRED` | точный старт из квитанции уже прошел | удалить локальную архивную квитанцию по явной команде |

Проверка `TAMPERED` выполняется раньше интерпретации содержимого. Поврежденная orphan-квитанция не используется для отмены: приложение не знает достоверный набор UID, времени и слотов.

## Порядок и счетчики

Полный порядок строгий и детерминированный:

1. состояние в последовательности `TAMPERED → REMOVED → UNRESOLVED → STALE → WITHDRAWN → CURRENT → EXPIRED`;
2. точный старт, если он известен;
3. исходный порядок активного каталога;
4. стабильный ID события.

Состояния от `TAMPERED` до `STALE` образуют очередь внимания. Панель показывает первые три таких события; если проблем нет, она показывает до трех активных записей, а при отсутствии активных — архив. Счетчики рассчитываются по всем квитанциям, включая строки за пределами трех видимых.

## Безопасный отзыв

Отзыв не удаляет локальную запись и не меняет календарь скрыто. После подтверждения приложение:

1. проверяет SHA-256 квитанции и seal исходного расписания;
2. увеличивает `SEQUENCE` без сброса цепочки;
3. создает `.ics` только с отменами прежних слотов и маркера старта;
4. сохраняет стабильные UID и исходные времена;
5. удаляет все `VALARM` и ставит `STATUS:CANCELLED`;
6. передает read-only URI через стандартный Android Share;
7. сохраняет квитанцию `WITHDRAWN` только после успешного запуска chooser.

Если событие снова появляется с точным стартом, следующий активный экспорт продолжает номер ревизии и использует те же правила стабильных UID. Отзыв не считается доказательством применения: обработка `SEQUENCE` и `STATUS:CANCELLED` зависит от внешнего календаря.

## Локальное удаление

Для завершенной или нечитаемой orphan-квитанции доступно отдельное действие «Удалить локальную квитанцию». Перед удалением интерфейс прямо предупреждает, что события во внешнем календаре не изменятся. Для будущей целой квитанции это действие недоступно: сначала предлагается безопасный отзыв.

## Контрольная метка

SHA-256 версии `sport-pulse-revision-radar-v1` связывает выбранную региональную зону и все упорядоченные строки: ID, название, вид спорта, регион, положение и наличие события в каталоге, точный старт, состояние, действие, метку локальной квитанции, текущий seal расписания и классифицированные расхождения. Поля кодируются с длиной, поэтому пользовательский текст не может изменить их границы. В метку входят и строки, скрытые за первыми тремя позициями.

Это локальный маркер воспроизводимости очереди. Он не является цифровой подписью, не подтверждает доставку `.ics` и не доказывает состояние внешнего календаря.

## Ограничения

- Радар работает только с квитанциями, созданными приложением после запуска Android Share.
- Приложение не имеет разрешения календаря и не может прочитать результат импорта.
- Удаление события из Event Pack не доказывает отмену реального спортивного события; радар отзывает только собственный календарный план проверки.
- Истекшая квитанция считается локальным архивом по времени старта, но приложение не удаляет ее автоматически.
- Для актуальных расписаний по-прежнему нужен лицензированный поставщик и официальная сверка.
