# Контрольная точка сюжета

«Контрольная точка сюжета» отвечает на вопрос «что содержательно изменилось с прошлого визита». Пользователь сам запечатывает текущую версию одного события, а приложение при следующем просмотре сравнивает ее с новым read-only расчетом «Сюжета» и «Маяка».

Это не автоматическая история посещений, не фоновый мониторинг и не журнал всех действий в «Лаборатории». Для каждого события хранится не больше одной явно созданной точки.

## Явный жизненный цикл

1. Без сохраненной точки панель показывает состояние `EMPTY` и команду «Запомнить эту версию».
2. Команда заново вычисляет текущий «Сюжет» и «Маяк» в момент нажатия и сохраняет запечатанный снимок.
3. При следующих открытиях приложение строит только смысловой diff с сохраненной версией.
4. Команда «Принять текущую версию» заменяет прежнюю точку новым снимком. Отдельная история версий не создается.
5. Пользователь может удалить валидную или поврежденную точку.

Простой просмотр ничего не сохраняет. В режиме тишины сравнение остается доступным для чтения, но создание, принятие и удаление точки заблокированы.

## Состав снимка

Точка связывает:

- стабильный ID и показанное название события;
- состояние источника афиши;
- состояния шести глав;
- фазу маршрута, следующее действие и его фактор;
- указанный старт и консервативную границу разбора;
- состояние и не больше пяти опорных моментов «Маяка»;
- полные SHA-256-метки исходных расчетов «Сюжета» и «Маяка»;
- локальное время явного сохранения.

Последние три технических поля защищают точную сохраненную запись, но сами по себе не создают пользовательский diff.

## Смысловой diff

Изменения объединяются максимум в пять видимых групп:

| Группа | Что считается изменением |
| --- | --- |
| Афиша / источник | название события или класс источника |
| Главы | переход состояния каждой из шести глав |
| Маршрут | фаза, следующее действие или выбранный фактор |
| Время | старт или граница разбора |
| Маяк | состояние или точный набор опорных моментов |

Счетчик изменений считает каждую измененную главу отдельно и по одному изменению для остальных полей. Течение времени, новое время вычисления и смена только внутренних меток «Сюжета» или «Маяка» не создают ложное сообщение.

Изменение уровня подтверждения в «Лаборатории» показывается здесь только тогда, когда оно действительно меняет главу, маршрут, время или «Маяк». Полный набор исходных факторов остается в «Лаборатории».

## Целостность

`StoryCheckpointCodec` использует формат версии `1` из 16 полей. ID и название кодируются Base64 URL без padding; enum-значения и времена имеют строгую форму; отсутствие значения обозначается `-`. Моменты «Маяка» кодируются как тип, время, действие и упорядоченный набор факторов.

Последнее поле содержит SHA-256 канонической строки остальных полей. При чтении проверяются:

- точное число полей и версия codec;
- все enum-значения, числа и Base64;
- инварианты снимка и моментов «Маяка»;
- совпадение ID с запрошенным событием;
- SHA-256 в constant-time сравнении.

Любая ошибка переводит запись в `TAMPERED`. Поврежденная точка не участвует в сравнении; панель сообщает о блокировке и предлагает только явное удаление.

Отдельная SHA-256-метка сравнения связывает сохраненный seal, текущую смысловую проекцию и точный набор дельт. Она не зависит от текущего `savedAt` и служебной смены внутренних меток, поэтому остается стабильной, пока пользовательский вывод не изменился.

Контрольные суммы показывают целостность и детерминированность локальных данных. Они не являются электронной подписью и не подтверждают внешний спортивный факт.

## Хранение и приватность

Точка хранится в закрытых `SharedPreferences` под ключом `story_checkpoint_<eventId>` и исключена из резервного копирования вместе с остальным состоянием приложения. Сеть, геолокация, уведомления, фоновые сервисы и новые разрешения не используются.

Удаление точки удаляет единственную сохраненную версию. Автоматического журнала визитов, аналитики возвращаемости и облачной синхронизации нет.

## Ограничения

Контрольная точка сравнивает две локальные версии продукта, а не официальный статус события. Она не узнает о переносе, отмене, результате или изменении состава без нового проверенного источника. Для production-сценария необходимы лицензированная афиша, аутентифицированные обновления и официальный источник статусов.
